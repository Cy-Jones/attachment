# Contributing to Attachment

Thanks for your interest in contributing to Attachment! We welcome contributions from the community — whether it's bug fixes, documentation improvements, or new features.

Before you contribute
- Read the README for project structure and setup steps.
- If you're planning a large feature, open an issue first to discuss scope and design.

How to contribute
1. Fork the repository and create a descriptive branch name:
   - git checkout -b feat/short-description
2. Install dependencies and run the test suite locally:
   - flutter pub get
   - flutter test
3. Format and lint your changes before submitting:
   - flutter format .
   - flutter analyze
4. Keep commits small and focused. Write clear commit messages.
5. Open a pull request against the main branch, referencing any related issues.

Pull request checklist
- [ ] My code follows the project code style (Dart formatting, Riverpod patterns used in this repo).
- [ ] I added tests for any new behavior (where practical).
- [ ] All existing and new tests pass locally.
- [ ] I updated documentation when applicable (README, comments).

Reporting issues
- Open an issue if you find a bug or want to request a feature. Include steps to reproduce, expected vs actual behavior, and environment details (OS, Flutter version, device/emulator).

Code of conduct
This project follows a Code of Conduct. By participating, you are expected to uphold it. Please read CODE_OF_CONDUCT.md for details.

License
By contributing, you agree that your contributions will be licensed under the project's existing license.

Thank you for helping improve Attachment!
